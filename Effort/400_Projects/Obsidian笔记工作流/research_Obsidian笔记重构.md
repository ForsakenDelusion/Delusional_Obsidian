# research_Obsidian笔记重构


## 为什么重构？

之前将obsidian做成了一个all in one的系统，包括学习记录，生活记录，博客管理，信息整理等等，导致我为了通用性做出了很大妥协，比如双链我就几乎没有使用，因为考虑到双链这种特殊的形式可能在其他markdown软件不兼容的问题。

后来我发现这种笔记的局限性很大。

- 首先层级混乱。这是一个历史遗留问题，在创建这个仓库之前，我并没有阅读其他作者的最佳实践，所以自己不断摸索导致这个仓库像屎山一样不优雅。
    
- 第二，没有双链的支持引发了三个问题。
    
    - 第一点：知识的重复”硬编码“。就是有很多知识，在很多不同的文章中都用过，但是由于对双链的排斥，我必须得每篇文章都得再写一遍这个知识来确保文章的连续性。第一是麻烦，第二是如果我有对这个知识的新理解，我还得修改很多篇文章。
        
    - 第二点：知识的复习。我认为有了双链的话，很多原子化的知识可以以卡片/闪卡的方式存在，这种形式的笔记非常容易复习。
        
    - 第三点：知识点之间的关联：有了双链的话知识点之间的关系才容易被发掘，有利于触类旁通。
        

边写边想大概总结了这么几点，所以现在的想法是将”输出“仓库（专门用来写文章与自己博客进行联动发布的仓库）和”知识“仓库（个人知识库，第二大脑）分隔开。这次重构我主要是想要构建出个人的知识仓库也就是PKM系统。  
  
这就是我重构仓库的上下文。

### 关于工作流程的Q&A

> 知识不是proj相关的，是从proj中充实自己的元知识库，让知识之间自发的产生联系

> 上手一个项目的时候，可能需要收集很多资料和文章，这些东西应该被收录到~~Sources~~底下
> 
> 但是这样引出了一些问题，比如Sources底下的子目录应该是怎样的，一般是根据学科分类对吧，那么我做一个proj的时候需要收集不同领域的文章的时候，岂不是需要来回在sources文件夹里面跳来跳去？以及摘录sources的时候应该如何摘录？是不是在proj的dashboard.md里面新建一个双链文件，这个双链文件是放在sources底下对应学科的底下，然后在手动填入source卡片的内容（url之类的）？并不是直接把文章拖进sources？
> 
> 上述的流程还是有些问题，Sources里面其实也应该是卡片的形式，sources里面应该是对广泛信息的第一次提炼，比如用自己的语言简述一个链接文章的内容。像是综述一样的东西,然后卡片的属性里面应该有源文件的url之类的。
> 
> 然后创建流程为
> - **在 Project 笔记中：** 你正在写项目文档。
 >   
>- **需要引用资料时：** 直接输入 `[[Sources/论文_Bustub优化策略]]`（假设你还没创建它）。
  >  
>- **点击创建：** 点击这个链接，Obsidian 会创建新文件。
  >  
>- **触发模板：** 此时结合插件（下文详述），自动应用 Source 模板，并将其归位到 `10_Sources/papers/` 下。
>    
>- **回到 Project：** 使用快捷键（如 `Ctrl+Alt+Left`）瞬间跳回 Project 笔记。

#### 用法思路

> - **在 Project 笔记中：** 你正在写项目文档。
 >   
>- **需要引用资料时：** 直接输入 `[[10_Sources/论文_Bustub优化策略]]`（假设你还没创建它）。
>- 引用卡片同理
  >  
>- **点击创建：** 点击这个链接，Obsidian 会创建新文件。
  >  
>- **触发模板：** 此时结合插件（下文详述），自动应用 Source 模板，并将其归位到 `10_Sources/example` 下。
>    
>- **回到 Project：** 使用快捷键（如 `Ctrl+Alt+Left`）瞬间跳回 Project 笔记。

比如读一篇论文的时候，可能需要对很多名词做解释，那就直接输入`[[Sources/xxx]]`，然后再cmd点击这个卡片创新卡片去解释一下这个

如果一个名词既有通用的解释，也有特定论文或者别的场景下的什么解释，那就依旧去这个卡片底下加内容，如果差异实在很大，那可以考虑创建一张特定场景下的新卡片，并且通过双链链接他们（在新卡片里写：“不同于 `[[认知负荷]]` 的通用定义，这里指的是…”）
